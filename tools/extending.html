扩展这套东西Extending it

三个接缝，都不在核心里面。核心只认识"文件、清单、摘要、落点"，引擎和压缩格式都是外接的。Three seams, none inside the core. The core knows files, manifests, digests and destinations; engines and archive formats plug in.

1. 再加一个引擎Another engine

游戏之外也一样：非游戏工程在概念上就是"又一个宿主"，用一个通用适配器描述它的落点与版本规则。This is also the answer for non-game projects: a project type is just another host, described by a generic adapter.

做法：新建 providers/engine-<名字>/，导出 <名字>Adapter，再在 apps/cli/lib/adapters.js 的 ADAPTERS 里加一行。核心文件一个都不用改。Add providers/engine-<name>/ exporting <name>Adapter, and one line in ADAPTERS in apps/cli/lib/adapters.js. No core file changes.

export const genericAdapter = {
  engine: 'generic',
  containerHandlers: [],          // 用普通压缩包就不需要写 handler
  meetsRequirement(engine, key, value, host) { /* 返回 true / false / 原因 */ },
  hostFacts(projectRoot) { /* 从工程里读出宿主版本 */ },
};

成员就是这几个：These are the members the core actually calls: engine · containerHandlers · meetsRequirement · hostFacts

2. 再加一种压缩格式Another container format

只有当制品不是 zip / tgz / tar.zst 时才需要：写一个 handler，注册到容器注册表。Only needed when the artifact is not zip / tgz / tar.zst: write a handler and register it.

registry.register({
  id: 'generic:mypkg',
  formats: ['mypkg'],
  inspect(bytes, artifact, context) { /* 返回 { items: [{ path, size }], entries } */ },
  async extract(bytes, artifact, context) { /* 写盘，返回实际写入的 items */ },
});

成员：Members: id · formats · inspect · extract

inspect 与 extract 必须对"会写出哪些文件"给出一致的答案——规划用它列落点，安装用它写盘，两者不一致就是"计划里说会装、装完少了文件"。inspect and extract must agree about which files exist: planning uses one, installing the other, and a mismatch is an install that silently misses files.

3. 自己写一个前端Your own front end

一个前端只做两件事：读注册库（index.yaml + payloads/*/tool.yaml），调 CLI 或复用 core。它不自己判断格式是否合法——那是校验器的职责。A front end does two things: read the registry, and call the CLI or reuse the core. It does not decide what is valid - that is the validator’s job.

契约写在 前端集成；为什么这样分工写在 前端设计。The contract is in Front-end integration; the reasoning behind it in Front-end design.

三条不变量Three invariants

  • 核心不装引擎：核心多一个引擎依赖，就是所有人为此付费。No engine in the core: one such dependency is paid for by everyone.
  • 规则只有一份：页面、CLI、CI 用同一份 schema 与同一个目录生成函数。One copy of the rules: pages, CLI and CI share the schema and the index builder.
  • 写盘只有一处：install / uninstall。页面能读能算，但不落文件。One writer: install / uninstall. Pages read and compute; they do not write.
