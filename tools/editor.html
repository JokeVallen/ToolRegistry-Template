1. 基本信息

小写字母、数字与单个连字符，3–64 字符。它是工具的主键：目录名、依赖引用、 制品文件名都以它为准，所以目录必须叫 payloads/<id>/。
不用查重：校验器要求目录名与 id 完全相同（E-ID-DIR）， 因此两个 payload 目录不可能同时占用一个 id——文件系统本身就是唯一性保证。本页不联网， 查不了整个注册库，也不需要查。
给人看的名字，显示在导入工具的列表里，1–80 字符。可以和 id 不同：id 是机器用的键， 这里是给人读的。用标题式大小写，短到能放进一行列表。
10–600 字符，一句话说清它做什么、解决什么问题。这是使用者在列表里做决定时读的那句话， 不是宣传语。
SPDX 标识符。写标识符本身，不要写整段许可证文本或 LICENSE 文件路径。 它可以与仓库整体许可证不同。列表只列常见几种，选「其他」即可手动填写任意标识符。
作者或组织名，1–80 字符。
半角或全角逗号都可以（, ， 、），最多 12 个， 每个是小写 kebab-case（editor、code-generation）。 建议复用已有标签而不是自造同义词——搜索的人猜不到你的新词。
本工具向别人提供的能力。点分小写名，至少两段 （script.api.argument-guards），不能是裸词。 逗号分隔，半角全角都行。
别的工具可以 injects 这个名字来要求"谁能给我这个能力"， 解析器会自动把提供者拉进安装计划——所以名字要选得能被别人猜到。 拿不准就先留空。
本工具需要、但由别人提供的能力。规则同 provides。
和下面 dependencies 的区别：injects 说"我需要这个能力， 谁提供都行"，由解析器挑一个提供者；dependencies 则是点名要某个工具。 能写 injects 就别写死 dependencies——那样会把自己锁死在某一个实现上。
点名依赖某个工具。能用 injects 表达就不要用这里， 因为写死 id 之后，对方改名或换实现，你也会跟着坏。
version 是范围（^1.1.0、~1.0.0、>=1.2.0），留空表示任意版本。 勾选"可选"表示缺了也能用。

2. 版本与引擎

semver-lite：主.次.修订，可带预发布后缀。
首版表单一次只填一个引擎的 target；多引擎见 template/tool.bundled.yaml。
真实下限，不要猜也不要省。
Unity 专用：宿主的 .NET API 级别下限，不是你这个库自己的目标框架。
这是最容易填错的一项。库用 .NET Standard 2.0 编译， 不代表这里要填 2.0——.NET Standard 2.0 是一份几乎每个运行时都实现的 可移植契约，而这里要填的是"最弱的、能真正加载这个程序集的宿主"。
格式必须是 主.次 两段：4.7.1 这种三段值会被拒绝。
常见取值：4.6（.NET Framework，2019.4–2020.3 的默认）、 4.7、4.8、6.0（Unity 2021.2+ 的 .NET Core 级别）。
拿不准就填 4.6：它从 2019.4 起都能装。 填高了只会缩小可安装范围，没有任何好处。留空表示不声明这一项。
