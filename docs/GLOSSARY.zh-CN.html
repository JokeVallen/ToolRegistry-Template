术语表

语言：中文 · English · 返回目录

一个词只用一个说法。本文固定注册库与导入工具共用的术语，以及几个容易被叫错的地方—— 那些名字相近、含义却不同的概念，是文档之间产生分歧的主要来源。

核心概念

术语英文含义
注册库registry本仓库。只存数据：元信息与制品。它不理解引擎，也不执行任何东西。
工具tool注册库里的一个可安装单位，由 payloads/<id>/ 一个目录代表。
元信息manifest一个工具的 tool.yaml。描述它是谁、需要什么、发布了哪些版本。
制品artifact真正被导入的东西：一个封存容器或单文件。注册库里唯一允许的二进制。
载荷payloadpayloads/<id>/ 这个目录。注意：它指位置，不指那个文件——文件叫制品。
目录文件index注册库根部的 index.yaml，所有工具的摘要清单，供导入工具一次读全。
回执receipt一次安装留下的记录，说明装了哪些文件、各自摘要是什么。卸载的唯一依据。
导入工具import toolToolImport/。它做解析、校验、安装，并写回执。

最常见的混用：制品 / 载荷。 载荷是位置（payloads/），制品是那个文件 （.../artifacts/x-1.0.0.unitypackage）。「把制品放进载荷目录」是对的；「下载载荷」是错的。

引擎相关

术语英文含义
引擎engineUnity、Godot 这类宿主。核心不认识任何具体引擎名。
targettarget某个版本面向某一个引擎的那一半：下限与制品。versions[].targets.<引擎名>。
适配器adapter一个引擎的实现，装在导入工具侧（providers/engine-*）。它贡献容器格式与下限比较。
核心corepackages/utool-core。引擎中立的解析、求解、校验、安装。
需求键requirement keytarget 的 requirements 里的一个键，例如 minEngineVersion。除 minEngineVersion 外都由适配器定义，核心不解释它们。
容器处理器container handler适配器注册给核心的钩子，用来打开某种专有格式（如 unitypackage）。

容易搞混：适配器 vs 前端。 适配器住在导入工具里，是 Node 代码，给核心提供引擎知识； 前端（frontends/unity-editor）是给人用的界面。一个引擎可以只有适配器没有前端。

依赖与能力

术语英文含义
依赖dependency「我需要这个工具」。按 id 钉死，写路径或 URL 是禁止的。
能力capability一个带命名空间的名字，如 script.api.argument-guards。至少两段点分小写。
提供provides「我能给出这个能力」。
注入injects「我需要这个能力，谁给都行」。与 dependency 的区别正在于不钉死提供者。
提供者provider某个能力的实现者。一个能力可以有多个提供者——它们是备选项，不是冲突。

能力冲突只在计划层。 注册库里同一能力有多个提供者只是警告（W-CAP-MULTIPLE， 它们是替代品）；把同一能力的两个提供者装进同一个工程才是硬错误（E-CAP-CONFLICT）， 因为消费者无法分辨自己拿到的是哪个。

版本与状态

术语英文含义
版本version一个已发布的号，形如 1.0.0。一个工具可以有多个。
latestlatest没有指定版本时默认安装的那个。必须是一个确实已发布的版本。
弃用deprecated「有更新的了，建议用新的」。仍可安装。
撤回yanked「这个版本坏了或有问题，禁止被自动选中」。与弃用是两件事。
约束constraint依赖里写的版本要求，如 ^1.1.0。
下限floor宿主的最低要求，如 minEngineVersion: '2020.3'。低于它则拒绝安装。

弃用 ≠ 撤回。 弃用是建议，撤回是禁止。被撤回的版本仍然列出，因为已有回执可能引用它。

制品类型

术语英文含义
archivearchive核心自己就能打开的通用容器：zip、tgz、tar.gz、tar.zst。
packagepackage只有某个引擎的适配器能打开的专有容器，如 unitypackage。
filefile没有容器的单文件制品：一个 dll、一个着色器、一份许可证。需要 targetPath。
externalexternal本仓库不存制品，只登记它在哪里（url + ref）。

关键区分：archive vs package。 前者是核心的知识，后者是引擎的知识。unitypackage 是 package 而不是 archive——这正是核心代码里没有 unitypackage 这个词的原因。
