Error code reference

Every code the toolchain can emit, in one place. Grouped by how you meet it, not by which module raises it.

Prefix: E- is a failure, W- is a warning (blocks nothing).

A missing or unparseable schema/tool.schema.json has no code of its own: it surfaces as a raw read error. That is a broken checkout, not a mistake in your manifest.

What may live here

Under payloads/<id>/, only:

payloads/<id>/
├─ tool.yaml            required
├─ artifacts/           required (may be absent for an external type)
│  └─ <id>-<version>[-<engine>].<ext>
└─ README.md            optional, only to say where an external source lives

Sources, DLLs, archives and backup files are not allowed — they would defeat the rule that only sealed artifacts are imported. Every file referenced by artifacts/ must be declared under versions, and artifacts/ must hold nothing undeclared.

Resolution

CodeMeaning
E-DEP-FETCHa dependency's manifest could not be fetched
E-CAP-CONFLICTwithin one install plan several tools provide one capability; the consumer cannot tell which it got
E-CAP-PROVIDERthe selected provider's manifest could not be loaded
E-CAP-PROVIDER-ENGINEthe only provider does not support the requested engine
E-CAP-PROVIDER-DEPthe provider's own dependencies are not in the plan, so it is refused rather than added halfway
E-PLATFORMthe host is below a declared floor; the error names the requirement and the tool that imposed it
E-PLATFORM-PARSEa floor cannot be compared (malformed value)

An engine adapter returns undefined for a requirement key it does not understand, never false. The core reads undefined as "this adapter cannot judge that", so it reports the floor without enforcing it. Returning false would block installs the moment someone adds a requirement key, which is exactly the coupling the adapter split exists to prevent.
